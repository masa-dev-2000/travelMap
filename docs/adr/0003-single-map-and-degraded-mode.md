# 0003: 公開地図を共通入口にして機能単位で縮退する

- Status: Accepted
- Date: 2026-09-18

## Context

公開閲覧と本人用画面が別入口だと、ログイン状態によって利用者が画面を行き来する必要がある。また、D1障害を画面全体の失敗として扱うと、データを使わない地図シェルまで利用不能になる。

## Decision

`/` を公開・ログイン共通の地図入口とする。公開地図と「みんな」の機能は常時読み込み、本人用機能はログイン時だけ `panel-me.js` を動的に読み込む。旧 `/admin/` は `/` へリダイレクトし、記録開始・編集など用途が明確な画面だけ `/admin/` 配下に残す。

D1由来データの取得に失敗しても地図シェルを表示する。公開記録は0件と誤表示せず、取得不能を明示して再読み込み手段を出す。ログイン済みの場合はその事実を保ち、私的APIは503と `data_unavailable` を返す。

## Consequences

- 利用者は同じ地図から公開閲覧と本人操作へ移れる。
- 公開・私的データの境界は `/api/public/*` と `/api/private/*` で明示される。
- 空データと取得障害を別のUI状態として扱う必要がある。
- データ障害中も地図、ログイン状態、復旧導線を利用できる一方、記録やプロフィールなどD1依存機能は停止する。
