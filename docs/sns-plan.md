# TravelMap 旅行SNS化 開発計画

作成 2026-09-18。ヒアリング（CSV 26問 + HTMLシート 15問）の回答に基づく。

## 期限
- **1週間：MVP**（自分がGoogleログインで使え、記録・編集・公開の絞り込みが動く）
- **1か月：ローンチ**（他人がGoogleログインで登録し、自分の記録を持てる）

## 確定した方針
| 項目 | 決定 |
|---|---|
| 認証 | **Googleログイン**。Cloudflare Accessは本人用の入口から外す |
| 公開の段階 | 4段階以上（そのまま／市区町村までぼかす／時間差公開／非公開） |
| ぼかし表示 | 市区町村名のみ。地図に点を出さない |
| 記録 | ワンタップ記録（アイコン→大ボタン1つ、時刻・位置＋カテゴリ「移動」固定） |
| 編集 | 日時・カテゴリ・メモ・金額・**位置（地図で移動）**・削除 |
| 閲覧者の絞り込み | カテゴリ・期間で地点と合計を絞る（他人の記録を見るときも） |
| お金の公開 | 予算・支出・収益まで。口座残高は出さない |
| 収益化 | 外部サービスへの投げ銭リンクのみ |
| 反応 | いいねではない何か。既存SNSの機能と課題を分析し、解決策を1つ実験する |
| コスト | 1人あたり月100円。古い写真は自動で縮小・削除 |
| 規約 | 他人を入れる直前に用意 |
| アプリ | PWA（ネイティブなし＝Apple審査とモデレーション義務を回避） |

## 第1週：MVP（自分用）
1. **Googleログイン**（最大の山）
   - Worker に OAuth 2.0 / OIDC を実装。`/auth/google` → Google → `/auth/callback` → セッションcookie（HttpOnly, Secure, SameSite=Lax）
   - `users` テーブル（id, google_sub, email, display_name, created_at）。既存298件は自分のuser_idに紐づけ
   - `activities` 等に `user_id` を追加（NOT NULL, 既定は自分）
   - `src/auth.ts`（17行）を置き換え。Accessの検証は移行期間だけ残し、切替後に削除
   - Google Cloud で OAuth クライアントを作る（本人操作。リダイレクトURIを登録）
2. **記録の編集・削除**：`PATCH /api/private/activities/:id`、`DELETE`。本人用一覧から編集
3. **公開の段階**：`public_entries` に `precision`（exact / city / hidden）と `publish_at`（時間差）を追加。配信時に丸める
4. **閲覧者の絞り込み**：公開APIにカテゴリ名を追加し、公開ページでカテゴリ・期間フィルタと合計表示

## 第2〜4週：ローンチ（他人が使える）
5. **ユーザーごとの公開ページ**：`/u/:handle`。プロフィール（名前・アイコン・ひとこと・訪問統計）
6. **フォローとフィード**（F3=c の希望）。ただし「反応」の設計が決まるまでは表示のみ
7. **反応の実験**：既存SNSの課題を分析 → 解決策を1つ実装（数字を出さない通知など）
8. **投げ銭リンク**：プロフィールに外部リンク欄
9. **規約・プライバシーポリシー**：自己責任の範囲を明記。削除請求の窓口
10. **コスト対策**：写真の枚数・サイズ上限、古い写真の縮小・削除バッチ
11. **PWA**：manifest とアイコン、ホーム画面から記録画面へ

## 重要な注意
- **Accessを外すと、認証の実装ミスが即座に公開漏れになる**。Googleログインの実装は、テスト（他人のセッションで他人の記録が読めないこと）を先に書く
- 既存データの `user_id` 付与は、**移行SQLを作って本番に流す前にローカルで検証**する
- Googleログインに必要な**クライアントIDとシークレット**はユーザーが取得し、`wrangler secret` で登録する（私はコンソール操作をしない）

## 検証
- テスト：他人のJWT／セッションでの私的API拒否、公開範囲の丸め、時間差公開、編集の権限
- ローカル：2人分のアカウントで、互いの記録が見えないこと
- 本番：自分のGoogleログイン、既存298件が自分の記録として見えること
